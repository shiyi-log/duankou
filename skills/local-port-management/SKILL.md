# 本地端口管理

共享本地登记表是项目端口归属的唯一依据。macOS 上登记表保存在 `~/Library/Application Support/LocalPortManager/registry.json`；不要将它复制到项目仓库。项目停止服务后仍保留其端口登记，避免其他项目占用。

## 规则

- 配置或启动本地服务前，先确认项目规范目录，并检查共享登记和当前 TCP 监听端口。管理器 API 可用时优先使用 API；不要为检查而覆盖或重写登记表。
- 某端口正在监听但没有对应项目登记，说明它被其他服务占用。不得将它分配给另一个项目，也不得仅凭进程名推定归属。报告冲突，并改用已登记给本项目的端口。
- 项目使用端口前必须先登记。拒绝使用其他项目已占用的端口，也拒绝已登记项目使用其登记范围以外的端口。
- 服务停止或项目暂时离线时仍保留端口登记。只有用户明确要求时才释放或转让登记。
- 管理器 API 可用时，通过 `GET /api/projects` 和 `GET /api/ports` 检查，通过 `POST /api/projects` 登记。`POST /api/projects/{id}/validate` 只确认端口登记给该项目，不代表端口当前空闲。启动前使用 `python3 portctl.py check --project <项目编号> --ports <端口列表>` 检查登记归属和当前占用。只有用户明确要求释放端口时才调用 `DELETE /api/projects/{id}`。
- 管理器 API 不可用时，只检查登记表，禁止覆盖原文件。若用户明确要求修改登记表，必须保留其他项目的登记，并使用带锁的原子更新。
- 禁止仅因进程占用冲突端口就结束该进程。先确认服务归属；更改其进程状态前必须取得明确的停止指令。
- 首选端口不可用时，不得临时使用未登记端口。先登记另一个空闲端口，再更新项目配置。
- 新项目登记时绑定项目的规范目录。已有监听只有在其工作目录与登记目录相同，或位于登记目录下且 Git 仓库根目录恰好等于登记目录时，才能认作该项目正在使用的端口。文件系统根目录和用户主目录不能用于认领监听；工作目录不可见或不匹配时也不得据此认领端口，应报告冲突。
- 在本仓库使用 `python3 portctl.py run --project <项目编号> --ports <端口列表> -- <启动命令>` 受管启动。它启动前重新检查登记与占用，固定使用登记目录，并监测本次启动进程组的 TCP 监听；出现未授权端口时只停止该进程组。
- 需要保活时添加 `--keepalive`，默认最多重启五次，每次重启前重新校验登记和占用。端口越权或冲突时停止重试。已有 supervisor 的项目先保留原有保活机制，避免重复启动。

## 能力边界

登记和受管启动约束适用于通过管理器使用端口的项目。目录匹配是工作目录归属检查，不是应用身份认证。受管启动只监测本次创建的进程组，不具备操作系统级端口隔离；直接绕过管理器启动、脱离受管进程组的程序和短于扫描间隔的监听可能无法被受管启动拦截。面板会报告扫描时观察到的未登记或目录不匹配监听。

## 汇报

端口不可用时，说明端口号、登记归属或观察到的监听服务；若已知，给出下一个可登记的端口。启动服务时，报告项目名称、分配端口，以及监听状态是否与登记一致。
